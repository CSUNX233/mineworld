本轮仅生成美术参考，不修改游戏代码、房间尺寸、寻路或随机生成逻辑。使用内置 imagegen，以用户认可的开阔荒庭概念图为风格参考。完整初始提示词与最终文件来源见 manifest.json，中文预览见 preview.html。

## 落地约束

1. 先生成玩法网格、障碍和连接，再按结果放地板、墙、拱门、装饰。图片不作为碰撞数据输入。
2. 当前 carveWide 在路径点周围挖 3×3 区域；直线可能斜向，折线弯点由随机逻辑决定。通路图中的三格是兼容核心，而不是未来理想宽度的最终定案。
3. 实际门洞取路径穿过房间边界的位置，可以偏心、多格、斜向或不止一个。参考图中居中端口仅为模块演示，不强迫生成器居中开门。
4. T／十字模块只覆盖已经存在的地面交汇，不能主动新增连接边。不要因建筑美术新增必须绕行的长路。
5. 接口在同一行走高度；上层拱廊、塔楼及远景先为装饰。若将平台做成可行走层，需另行完成高度碰撞、寻路与攻击验证。
6. 建筑高度约4–10单位是提案，独立于现有两格墙体；英雄1.8单位也是图内尺度参考，不改当前角色碰撞体。高墙需要同步解决镜头遮挡。
7. 退让墙体、宽前庭和远景可增加宽阔感，但只能使用实际可用边界。临近房间紧凑时降低／省略外围装饰，不能覆盖相邻地面。
8. 未连接的端口封墙；有连接的端口保持净空。屏障只覆盖真实入口截面，不将门柱或大型实体门放进落脚区域。
9. 每种房间的局部障碍以 rooms.ts 和运行时装饰规则为准。图中拱门、雕像、货架比例和位置不是逐格精确结果。
10. 补给货架原始逻辑为纵向，中央三格开启；两端始终可绕行。04图前后小示意旋转了视向，制作时勿据此把整个货架改成横向。
11. 支持对房间实际边缘裁切、对直段重复铺设、对模块旋转；不把整个房间模型固定成只能连接四个正中端口的预制块。
12. 功能房里的喷泉、兵种、商店外观仅表达角色。恢复、怪物配置、奖励与商店出现仍遵循当前数据，不能从图中增加交互或改怪。
