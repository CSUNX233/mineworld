本页保留 P0 对照规则。当前 P1 已增加营地、25 层单局与阶段/胜负结算，现行流程及待验收内容见 [P1 交付说明](P1_DELIVERY.md)；下文旧的死亡复活与无限楼层不代表 P1 行为。

## 1. P0 范围与可复现边界

- 新开局可用 URL 参数固定 run seed，例如 `http://127.0.0.1:5173/?seed=42`。建议对照 seed 为 `0 / 42 / 311 / 777`，重点观察第 `1 / 3 / 5` 层。
- 参数只作用于**新开局**；“继续游戏”读取存档内原 seed，不应被当前 URL 的 `?seed=` 覆盖。源码中的存档字段包含 `seed`、楼层、房间进度、怪物、宝箱、商店库存与交易次数，见 [Game.ts](../src/core/Game.ts)、[SaveManager.ts](../src/core/SaveManager.ts)。
- run seed 与楼层号先组合为 floor seed；地图、房间模板、遭遇生成和商店库存使用种子 RNG。因此固定 seed 适合比较地图与遭遇。
- **不能称掉落也可复现。** 怪物金币数、药水/装备/重铸券概率、普通装备生成、暴击与部分装备触发仍直接使用 `Math.random()`，见 [LootSystem.ts](../src/items/LootSystem.ts)、[ItemGenerator.ts](../src/items/ItemGenerator.ts) 和 [Game.ts](../src/core/Game.ts)。同 seed、同路线仍可能获得不同掉落与战斗结果。
- 第 1 层用于检查开局、近战敌群和基本探索；第 3 层开始能稳定进入远程角色池；第 5 层检查首个 Boss。四个 seed 用于对照整体旋转、模板、可选连边和商人位置；实际出现了哪些差异由玩家记录，且这些样本不代表完整随机空间。

| 楼层 | 后续可选对照内容（本次不要求遍历四个 seed） | 代码已知重点 |
| --- | --- | --- |
| 1 | 两个主线房的路线、重复模板、第一次资源收支 | 角色池只有近战定义，遭遇虽请求远程位但会回退到通用池 |
| 3 | 远程压力、掩体作用、路径是否仍像同一九宫格 | 骷髅射手已开放；第三个“冲锋位”尚无可用冲锋怪，会回退到通用池 |
| 5 | Boss 房、警示可读性、普通房与 Boss 房差异 | 出口房生成 Boss 加两只普通怪；Boss 有三阶段、锥形/圆形预警、冲刺与召唤 |

## 2. 当前实际流程

代码已确认的流程如下：

1. 对照提交的主菜单直接显示三个本地存档位。P0 验收追加需求已改为“开始游戏 → 存档界面”，提供五个存档位：空槽新开，已有存档继续或确认删除；原前三槽的键名不变，兼容旧存档。
2. 新游戏从第 1 层、Lv.1、0 金币、空材料、空背包和空装备开始。游戏自动保存到 `localStorage`，并约每 4 秒再次保存。
3. 每层生成一个 40×40 地图和九个固定位置的 10×10 功能房。进入战斗、精英或出口房时才生成该房遭遇。
4. 每层固定两个必做房。清完二者后传送门激活；其他战斗、精英、宝藏、圣所和商店均可选。
5. 传送门处必须选择一次仍未满级的层间专精，然后进入下一层。三种专精各三级，九次选择后全部点满；楼层没有上限或胜利结算。
6. 每 5 层的出口房出现同一个“深渊领主”Boss。地图主题每五层切换一次，当前第 1–5 层仍属于同一洞穴主题。
7. 死亡不结束单局：当前层重新生成、生命和法力回满、金币扣 10%，角色等级、装备、背包、材料和专精保留。`deathTimer` 在基线代码中没有被设置为正值，因此复活流程会在后续更新中立即执行；实际视觉感受待试玩。
8. 返回主菜单先保存；继续游戏恢复同一 seed 和已保存的当前层状态。

主要证据：[FloorGenerator.ts](../src/world/FloorGenerator.ts)、[EncounterDirector.ts](../src/core/EncounterDirector.ts)、[MonsterSpawner.ts](../src/monsters/MonsterSpawner.ts)、[BuildSystem.ts](../src/items/BuildSystem.ts)、[Game.ts](../src/core/Game.ts)。

## 3. 已知操作与目标设备

目标设备信息目前只有“手机横屏优先、竖屏兼容”。实际手机型号、操作系统、浏览器、视口、刷新率和性能档均未知，留待玩家验收时记录；本阶段不填写假设备，也不声称达到任何帧率目标。

键鼠关键操作：WASD 移动，鼠标转向，Shift 冲刺，空格跳跃，左键普攻；数字键 1–3 使用默认主动技能，4–5 使用解锁后的技能；E 交互；Tab/B 背包；P 属性/天赋；K 技能配置；C 切换第一/第三人称；R 让第三人称镜头回正；滚轮调镜头距离，按住右键保持面向；Esc 暂停或关闭当前面板。画面需点击取得鼠标锁定。

移动端关键操作：左摇杆 360° 移动，轻推慢走、外推冲刺；拖动非 UI 画面转向；独立普攻、跳跃、暂停按钮；四个技能位；靠近宝箱、圣所、商人或传送门时出现情境交互按钮；另有背包、人称切换、技能配置入口。系统返回键按面板层级关闭详情/面板。横屏背包左右分区，竖屏以页签切换。实现证据见 [TouchControls.ts](../src/ui/TouchControls.ts)、[InputManager.ts](../src/core/InputManager.ts)、[PlayerController.ts](../src/player/PlayerController.ts) 和 [InventoryUI.ts](../src/ui/InventoryUI.ts)。

## 4. 金币与材料产消基线

下表是静态规则，不是玩家实际每层收入。令 `F` 为楼层，`L` 为幸运属性。

| 资源 | 产出/消耗入口 | 基线规则 | 静态结论与待观察点 |
| --- | --- | --- | --- |
| 金币：怪物 | 每只怪必掉 | `round((3 + 2F + random(0, 4F)) × (1 + L/100))` | 非种子 RNG；必须用导出记录实际分布 |
| 金币：清房 | 战斗/出口房，精英房 | 普通 `10 + 2F`；精英 `30 + 5F` | 每层两个必做房，另有可选房；精英怪本身还有下行奖金 |
| 金币：精英击杀 | 标记为 elite 的怪 | `8 + 3F` | 精英房首只怪固定为 elite |
| 金币：宝箱 | 每层一个宝藏房 | `10 + 3F`，另给装备和 1 张重铸券 | 装备生成仍非种子 RNG |
| 金币：出售 | 仅地图商店 | 装备按 `sellPrice`；材料按材料基价并每深入一层增加 4% | 商人随机出现，但每三层至少一层固定有商人 |
| 金币：死亡 | 死亡复活 | 扣当前金币的 `floor(10%)` | 不结算、不清空本局资产，存在同层反复获取收益的设计风险 |
| 金币：购买 | 商店四件库存 | 不低于分解/出售回收估值的 125%，并受物品等级、品质定价下限约束 | 库存按 seed 和楼层生成，购买后移除 |
| 金币：换货 | 商店，每层最多 3 次 | `ceil(预估主线层收入 × 0.2 × (1 + 已换次数))` | 价格递增；次数和库存进存档 |
| 金币：部位委托 | 商店，每层最多 3 次 | 不低于 `预估主线层收入 × 0.65`，并高于期望回收值 35% | 给指定部位但品质随机 |
| 金币：补给 | 商店，每层最多 2 次 | `ceil(预估主线层收入 × 0.25)`，恢复 40% 生命/法力 | 满状态不能购买 |
| 金币+材料：升级 | 背包装备打造 | 金币 `(25 + 8×物品等级) × 品质序号`；消耗一种主材料，物品等级 ≥5 再固定消耗 1 元素碎片 | 每次只提高 1 级，基础数值约乘 1.055；攻击速度不升级 |
| 材料：分解 | 单件或批量 | 按品质、部位映射一种主材料；数量约为 `round(物品等级/3 × 品质序号)`，传说再 ×2 | 已穿戴装备不参与批量分解 |
| 重铸券 | 怪物 2% 概率、宝箱固定 1 张 | 重铸消耗 1 张，重新随机全部词条 | `CraftingSystem.reforgeCost()` 的金币/材料公式未被当前 UI 流程调用 |

材料映射存在三个代码已确认的缺口，需在 P5 经济联合调整前保留：

- `materialForItem()` 按铁→银→金→秘银→元素碎片→虚空精华返回第一个匹配项。稀有胸甲、护腿和靴子没有任何匹配，分解结果为空。
- 元素碎片实际上只会由传说戒指/项链落入当前“首个匹配”路径；但所有物品从等级 5 起升级都需要它，构成明显的供需瓶颈。实际卡住频率待试玩统计。
- 虚空精华的所有声明来源都会先匹配秘银或元素碎片，所以现有分解路径不会产出虚空精华。这是静态接线结论，不是概率猜测。

主要证据：[LootSystem.ts](../src/items/LootSystem.ts)、[ShopSystem.ts](../src/items/ShopSystem.ts)、[CraftingSystem.ts](../src/items/CraftingSystem.ts)、[materials.ts](../src/data/materials.ts)、[Game.ts](../src/core/Game.ts)。

| 远程怪 | 保持约 78% 射程，太近后退、合适距离横移、超距接近 | 比近战更有空间压力，但多个远程定义共享相同行为 | 掩体是否可靠、预警和弹道是否清晰 |
| 冲锋怪 | 使用近战逻辑，仅移动速度 ×1.25、前摇 0.65 秒 | 名称上是冲锋，缺少独立蓄力路线、冲刺轨迹或碰撞机制 | 玩家是否感知为更快的近战怪 |
| 精英 | 精英房首只怪只固定 `extraHealth`，生命再 ×1.6；普通遭遇不调用随机精英修饰器 | 精英房核心差异接近“血更厚”；火焰、吸血等代码路径在常规精英房不出现 | 精英房是否只是耗时更长 |
| Boss | 每 5 层同一 Boss；有三阶段、锥形/圆形预警、冲刺、最终阶段召唤 | Boss 机制明显多于普通怪，但长期重复、空间和组合仍单一 | 第 5 层预警是否可读、召唤与障碍是否造成无解夹击 |
| 数值成长 | 怪物生命每层约 +18%，攻击 +12%，经验 +10% | 内容不足时容易由线性数值替代难度变化 | 死亡是否来自可解释机制，不能只记录“数值太高” |
| 主题 | 四套主题，每五层切换；主题不改变房图、怪物职责或规则 | 换材质/颜色可能被误当成新地图内容 | 主题是否只改变外观 |

## 6. 装备、词条与套装静态风险审计

### 代码已确认

- 当前有 49 个基础物品定义，其中 46 个带 `setId`。普通掉落从全部基础物品均匀挑选时，约 94% 的基础结果属于套装；这会让“散件”在内容池中天然稀少。
- 数值词条共 18 个，每个属性只有一个定义，差异主要是属性种类、数值区间和允许部位。品质决定词条数量：普通 0、魔法 1–2、稀有 2–4、史诗 4–5、传说 5–6；传说还会额外附加一个特殊词条，因此实际可达到 6–7 条。
- 词条在同一件装备内按 id 去重；所有基础属性、词条数值和已激活套装数值直接相加。套装阈值累计生效，没有取舍或预算机制。
- `agility` 会生成、显示、分配并计入总属性，但 `getDerivedStats()` 没有读取它。敏捷词条与敏捷加点当前不会改变派生战斗属性，这是已确认的接线缺陷。
- 九个传说特殊词条都有 `Game` 中的规则消费：连锁闪电、击杀爆炸、移动护盾、陨石、击杀召唤、满血增伤、冲刺无敌、火焰路径、低血护盾。
- 五个套装 special——`burnMastery`、`freezeMastery`、`glacialNova`、`poisonMastery`、`shockMastery`——只有定义和 UI 文案，未发现战斗规则读取；对应套装的数值部分仍会生效。这是静态接线缺陷，不代表其他套装特殊效果失效。
- 特殊效果以字符串集合和 `hasSpecial()` 判断，同名效果来自词条与套装时只表现为“有/无”，不会因多个来源叠加次数。
- 重铸会重随机全部词条，不能保留单词条；升级只乘基础属性，不提高已有词条。装备 id 同时承担实例标识，升级/重铸会生成新 id，不适合作永久图鉴主键。

### 风险，尚无玩法实证

| 风险 | 静态依据 | 后续验收 |
| --- | --- | --- |
| 套装压过散件/混搭 | 46/49 基础物品带套装，且阈值奖励累计 | P5 对同成本纯套、混搭、散件比较实际伤害、生存与机制用途 |
| 词条同质化 | 每个数值属性只有一个词条定义，多数改变面板数值 | 统计实际穿戴率和淘汰率，确认是否存在无条件最优属性 |
| 无效内容污染池 | 敏捷无派生效果；五个套装 special 未接入规则 | 修复前先记录获得/穿戴情况；修复后做规则级验证 |
| 高等级打造卡料 | Lv.5+ 升级必需元素碎片，而现有分解来源极窄 | 记录首次获得碎片时间、升级尝试与材料结余，不能预先捏造卡点 |

## 7. P0 本地试玩记录

P0 观察工具从玩家选择“新游戏”或“继续游戏”开始一段**页面内试玩会话**，记录会话模式、seed、存档位、起始楼层与起始资源，并记录楼层进入、遭遇开始/完成、死亡、物品获取、打造、商店交易、金币增减和资源快照。它按探索/战斗/菜单累计前台时间；页面隐藏时不计时，恢复后的首帧间隔也丢弃。

暂停菜单显示本局 seed，并提供“导出试玩记录”。导出 JSON 只来自当前页面内存：最多保留最近 2000 条事件，超出部分计入 `droppedEventCount`；不上传、不写入游戏存档，刷新页面后消失。再次从主菜单选择新开或继续会开始新的观察会话。导出的 `sessionSeconds` 是前台页面会话时间，不应直接称为完整单局时长。

事件总计、分类时长与 `goldSummary` 的收入/支出/按来源汇总覆盖整个当前会话，不随旧事件淘汰而丢失。`metadata.initialGold + goldSummary.net` 可与导出时 `resource_snapshot` 的金币余额核对。时间分类是近似口径：有菜单时归菜单，否则存在存活怪物归战斗，其余归探索；没有进行走路、空转或实际交战时长的精确识别。死亡记录区分近战、投射物、Boss 技能、持续状态伤害等，状态列表仅作上下文，不代表已锁定具体致死状态。

## 8. 本阶段最短手动验收

本阶段由用户亲自验收；验收后再决定是否进入 P1。当前不要求全套自动化、跨浏览器、压力、完整平衡或性能测试。

1. **新开：** 用 `?seed=42` 点击“开始游戏”，在五槽存档界面选择一个空槽，进入第 1 层；暂停菜单确认显示 seed 42。移动、普攻、技能和一次交互可用。
2. **继续：** 返回主菜单后继续同一槽，确认楼层/角色资源/房间进度可恢复，seed 仍为 42；即使把 URL 改成其他 seed，也应保留存档原 seed。
3. **暂停导出：** 暂停并导出 JSON，确认包含 `mode`、seed、楼层/遭遇事件、时间分组和金币汇总；切到后台一会儿后恢复，隐藏时间不应计入。
4. **可选——死亡：** 让角色死亡一次，确认仍按旧规则复活、损失 10% 金币，并检查 `player_died` 与死亡罚金记录。填写实际死因，不从代码猜测。
5. **可选——商店：** 完成一笔购买、换货、委托、补给、装备出售或材料出售，确认余额和 `shop_transaction` / `gold_changed` 对应。
6. **存档管理追加验收：** 在不需要保留的试玩槽点击删除，先取消确认，存档应保留；再确认删除，该槽应变为空位，其他槽不变。空位可以重新开始；存档界面的返回按钮回到主菜单。
