# 第一批性能优化与行为对照

本批只减少重复计算、临时分配和界面布局工作，不调整数值、随机数调用顺序、伤害数字数量、结算规则或保存时机。

## 已完成

- 投射物：增加四单位空间网格，候选按原怪物顺序排序；保留原精确射线检测。每帧按需建立索引，在命中或过期回调可能造成击退、死亡、召唤之后重新建立，避免同帧旧位置。超长弹道回退到全量候选；复用单颗投射物的碰撞盒。
- 属性：独立 EffectiveStatsCache，沿用装备属性缓存的失效机制，并对比局外天赋数组内容，支持加载替换及原地编辑。最终公式不变。
- 伤害数字：复用容器和投影向量，使用 transform 位移；只限制空闲池为 128 个，不限制活跃数字。保留原暴击子元素动画、颜色、寿命、数量和随机轨迹。
- 存档：独立 SaveCandidate，只跳过深拷贝即将被替换的旧 snapshot；保留完整历史、营地、revision、原子 localStorage 写入和失败重试机制。
- Game 的空间候选、最终属性缓存、存档候选准备已有独立职责模块。整个战斗执行和菜单导航尚未全部迁出，不能称为已完成 Game 全面解耦。

## 对照检查

`node --test tests/performance-parity.test.mjs`

1. 800 组固定随机碰撞场景，与冻结的优化前实现比较命中对象、位置、生命期和穿透记录。
2. 击退移动与新怪物生成后重建候选，同距离目标保留原结果。
3. 数字逻辑使用轻量 DOM 替身，对照轨迹、数量、寿命、屏幕位置和池复用；不等于真实浏览器视觉验收。
4. 所有永久天赋逐项累加，对比原属性公式，并检查数组内容和基础属性变化。
5. 存档候选与原先 clone-and-replace 的对象及 JSON 完全相等，原输入不被修改。

构建通过，既有玩法修复与召唤检查通过。未进行手机帧耗时测量，不宣称固定 FPS 提升或全部游戏状态均已证明等价。

## 后续边界

不在本批迁移 IndexedDB、延迟保存或减少保存频率，避免改变异常退出时的存档语义。共享营地全量序列化仍存在。Game 的流程、菜单及战斗执行应按独立阶段逐个迁出，每个阶段单独对照；不要一次改写所有系统。

## 第二批：投射物生命周期与 HUD 更新

- 新增 ProjectileRuntime，由独立模块处理逆序遍历、移动结果应用、穿透扣次、命中/过期优先级和销毁。Game 通过稳定的 host 回调提供伤害与表现行为，回调对象不逐帧创建。伤害公式和元素触发链仍留在 Game，未声称整个战斗系统完成迁出。
- 保留原暂停中断位置：命中伤害导致暂停时立即退出，不继续触发元素效果或销毁；其他原有回调的检查位置不移动。
- 保留原始数组动态访问及空间索引失效机制，防止命中引起怪物变化后使用旧位置。
- HUD 等级/经验、楼层/金币/怪物/击杀、蓄势图标只在显示内容变化时重建。血槽插值、状态计时、技能冷却和 10Hz 状态同步频率不变。

验证：投射物 16 种命中、过期、暂停组合检查通过；既有 800 组碰撞对照继续通过。HUD 使用 DOM 替身验证连续 20 次无变化刷新保持节点、变化时更新以及血量目标持续变化。`npm run build` 通过。未进行实机 FPS 测量，DOM 替身不代表完整视觉验收。
