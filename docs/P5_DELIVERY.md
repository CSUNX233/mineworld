# P5 交付说明

日期：2026-09-12。对应 `P5_EQUIPMENT_DESIGN.md` 的机制套装、混搭与有限打造阶段。

本轮交付以可试玩代码为准：12 套新版机制、真实装备部位池、独立套装运行状态、定向与保留重铸，以及奖励和商店的获取辅助。完成的是实现与基本逻辑核对；成熟期同预算综合表现差距不超过 10% **仍是设计目标，未经过实战对照证明**。清群、精英、无小怪首领、生存、资源效率和手机操作体验均待实战验收。本轮没有百局玩家模拟或长时间压力测试。

## 1. 装备规则与十二套机制

## 2. 混搭与预算

每套提供武器、头、胸、腿、鞋、戒指、项链、副手八种底材，共 96 个稳定底材 id。双戒指形成九个实际装备槽，同底材两枚戒指可以分别计件。新版同部位套装基础属性预算一致；通用旅者散件基础数值补偿 8%，基础攻速不增加，作为末槽和放弃套装机会成本的补偿。底材数量不是玩法数量。

装备结构支持 `4+4+1`、`4+2+2+1`、`2+2+2+2+1`。基本检查枚举全部 66 对套装的实际 `4+4` 穿戴，验证件数和机制激活。部位可穿不代表全部组合强度相当或技能位相容：近战与施法武器、编队单位、主动技能仍有真实选择成本。

可试玩的主题搭档包括战争领主＋破军／血裔、霜语者＋永冻／风暴、暗影＋破军／烬钢、炼狱＋烬钢／霜语者、疫毒＋魂旗军团／烬祭、魂旗军团＋烬祭／血裔。这些是机制上的协作方向，未做胜率或最优构筑排名。

每套伤害预算按参考普攻伤害率生成：2 件每战斗秒 6%，4 件 12%，最多积攒三秒；群体触发分摊同一总额。全套装共享护盾与法力恢复预算，分别按每战斗秒最大生命的 0.6% 和最大法力的 0.8% 生成，最多积攒五秒。该预算约束额外效果，不等于整套综合强度或最终伤害必然达到某个比例。护甲、抗性、触发条件、资源机会成本和命中窗口仍会影响结果。

套装详情和物品提示直接使用数据中的机制说明及 `runtimeHint`；独立详情显示版本、已激活档和下一档，纯机制套装也能显示。背包摘要保持简洁，详情内容在 PC 和手机横竖屏滚动。

## 3. 有限打造与获取辅助

普通词条新增淬炼（基础攻击提高8%–16%）、深储（基础法力提高10%–20%）、层铸（基础护甲护盾提高12%–24%）、长生（基础生命提高6%–12%），以上为1级范围，沿用每物品等级2.5%的词条范围成长。它们与原有固定值词条形成随底材成长的选择；百分比只乘基础属性，不乘其他固定加成，不逐条复利，较低权重避免挤占原有池。吸血、暴击、闪避、攻速、冷却与护盾恢复继续沿用已有总上限；未添加伪元素伤害词条。

每件装备最多重铸三次，普通、定向和保留重铸均消耗一次。可从本底材实际普通词条池选择近战、火焰、冰霜、闪电、毒、召唤、资源、防御方向；选定标签只把对应候选权重提高至三倍，其他结果仍可能出现，不保证最高数值。现有元素和召唤标签偏向真实辅助属性，不虚构池中不存在的专属元素伤害或召唤单位。

允许保留一个现有普通词条，保留名称、数值和数值模式；所有特殊机制自动原样保留，不能作为普通池的重抽目标。没有可重抽词条的白装、锁住唯一普通词条、无效标签和耗尽额度会显示原因并拒绝操作。没有炸装或降品质，重铸不改变装备基础属性。

费用继续使用金币和现有材料。定向增加基础金币的 25% 及一个元素碎片，保留增加 50% 及一个碎片，合用增加 75% 及两个碎片。面板显示合计费用、当前持有量、真实等级／品质词条范围、剩余次数，并在不足时禁用确认；确认执行时再次校验费用与目标装备。强化和重铸保留实例 `id`、稳定 `contentId` 和打造进度，强化不恢复重铸额度。

开局选择主研究流派与一个可选辅助机制偏好。40% 的部分候选走固定主流派套装池，并在池内优先匹配辅助机制；其余保留通用／偶遇来源，不提高稀有度。所有新局奖励与商店生成使用同一版本和偏好入口。

前五层首个符合条件的精英提供一次同套、不同部位的两件启动奖励，以 `p5StarterGranted` 记录领取状态；这提供小循环获取机会，不保证任意构筑都能立即满足技能前置。商店继续三层保底和有限刷新、委托次数；缺部位委托按当前穿戴最多且不足四件的新版套装提供补件并注明套名；标★的缺部位保证该套，其他部位仍随机，品质和普通词条不保证。商店也可按材料出售单价的1.5倍购买一个元素碎片，与装备委托共用每层三次额度。重铸券自动按1:1兑换元素碎片（含旧档余额与新拾取），连接探索奖励和有限打造，不另设新货币。前五层启动、六至十层形成主循环的整体节奏仍待试玩验证。

经济收口修复了旧强化售价每次乘1.2的指数增长：生成、强化和商店估值共用线性公式 `(5 + 2 × 物品等级) × 品质序号²`。基本检查覆盖1/10/25层购买后连续强化再出售或分解的路径，回收低于购买与打造成本。未批量改写旧档已有售价；它们下一次强化时归一。随机委托仍可偶遇较高品质收益，但不是确定获利，且次数受限。

## 4. 保存、兼容与工程边界

缺少 `equipmentRulesVersion` 的装备和旧局按版本 1 解析，继续使用旧九套原有档位与属性；同一稳定套装 id 的新旧装备分别计件，不能混合凑出新版两件。新版局和装备显式记录版本 2，界面标注旧版装备。共同营地与独立单局边界沿用已有存档结构。

物品 `reforgeCount` 随保存保留，旧装备缺省按尚未重铸处理；共用打造接口的三次额度也适用于旧装备。单局保存打造随机序列，读档不重抽同一序列来绕过下一次结果。套装积层、计时、冷却和剩余预算保存为 `SetSnapshot`；不足两件时清积层及该套伤害余额，保留冷却，重新穿戴不能立即重领触发收益。

延迟攻击的目标引用不跨换层或读档保留，已经预扣的伤害不退回；因此读档后某次尚未落地的残影／余震可能消失，这一边界用于避免重复结算，不宣称延迟表现完全逐帧还原。疫骸继续使用共同召唤容量及已有编队保存机制。

本轮复用现有装备图标、粗模、状态图示和效果表现，没有新增图片制作要求。P6 图鉴、P7 暗金、高阶地图、风险打造与技能转化不在本轮交付范围。

## 5. 基本检查与待验收项

相关基本检查位于 `tests/p5-equipment.test.mjs`、`tests/p5-crafting.test.mjs`、`tests/p5-runtime.test.mjs`、`tests/p5-save-validation.test.mjs` 和 `tests/p5-economy.test.mjs`：覆盖十二套定义、96 个唯一底材、全套装配对部位可行性、双戒指、版本分离、生成偏好、锁定词条与特殊机制保留、三次额度、实际候选预览、十二套触发路径、共享预算、群体分摊、补编付费条件、卸装和保存边界。运行时测试使用固定事件与首领替身，证明基本条件和预算路径能执行，不能当作真实首领战、真人胜率或全场景平衡实测。

本次 `npm run build` 通过（包含类型检查）；上述五个 P5 文件的30项检查及既有 core 文件12项检查，共42项全部通过。core包含固定种子的地图/商店基本回归，不是42局或百局实战。只进行基本逻辑检查，进入试玩验收。仍需用户实战观察：每套入口是否足够清楚、首领战是否容易启动、典型混搭是否有实际收益、散件是否有竞争力、获取节奏和金币材料是否合理、手机操作按钮是否始终可达，以及成熟期清群／精英／首领／生存／资源的综合差距。**10% 仅是后续对照目标，本文件不是达标证明。**
