## 统一风格与投入

- 制作投入顺序：主角 > Boss > 普通敌人。主角优先保证背面、侧面、手部、武器与动作质量；每位 Boss 保留独立大轮廓；小怪按骨架和功能复用。
- 延续 Sunlit Quest 的暖奶油、靛蓝、青绿、陶土与章节色板。造型采用可辨认的斜面、削角、锥形四肢，避免方块头、等宽方柱四肢和已有游戏的标志性服饰。
- 借鉴同类游戏的大轮廓可读性、材质分组和动作节奏，不复制其角色、图标、纹样或特效素材。主角原创识别点为短兜帽、分片陶瓷面罩、腰侧六角星火容器。
- 像素块主要属于贴图，不应把参考图每一个像素块都建成独立立方体。主要几何用于轮廓、关节、武器厚度与变形部件；裂纹、铆钉、衣纹放入共享图集。
- 手机横屏为第一验收视角：主角轮廓最稳定，敌人攻击部位和机制道具第二，局部饰纹最后。不能仅以换色区分治疗、远程、隐身和盾卫。

## 主角与武器

「星火行者」为视觉工作名，不改游戏身份或剧情。短兜帽、青绿不对称披肩、靛蓝短衣、陶土皮革与奶油色分片面罩；腰灯是辨识附件，不赋予新技能。

保留独立左右手挂点。右手的武器以握柄原点、攻击轴和统一尺度定位，剑、锤、镰、杖共用挂接协议，各有握持与挥动姿态；有需要时左手辅助握持。武器正背面可用装备像素图，边缘有薄体或简化模型，避免侧面消失。装备图标往往带留白、透视和图标光效，不能原样贴到整张矩形面片上；后续应按物品 ID 准备武器外观映射、裁切/透明素材与握柄偏移，并提供缺省外观。

现有 `Player.setWeapon` 已有右臂挂接但以程序生成剑/杖为主；本轮仅确定替换规格，不修改该入口。参考图里的基础示例武器不覆盖已选套装和五把 Boss 专武的外观设计。保持 Boss 专武、死亡收割镰与原有图鉴的身份对应。

模型动画与战斗判定分离：沿现有出手时刻落接触帧，挥刀轨迹沿武器攻击平面；不得为了动作图改变技能命中时刻、攻击距离、冷却或碰撞。第一人称单独检查手腕与握柄近景，披肩不能挡住视线。

## 小怪复用与覆盖

代码注册表由 `monsters.json`、`RuinsMonsters.ts`、`SanctumMonsters.ts`、`LateMonsters.ts` 合并：共 40 种敌人，其中 35 种非 Boss、5 位 Boss。包含仍可由通用生成池或旧存档引用的敌人，不因当前章节首遇少而遗漏。

参考图按十一组组织：步卒、射手、遗迹施法者、重甲与军旗、铸造所人形、机械构装、软体元素、恶魔石魔幽灵、送葬负棺、铭刻封印、裂影机制怪。图组不等于一个模型：例如撞锤兽、棱镜哨兵、镇印执械分别需要四足、底座转台、重型双足结构。

可复用层次：骨骼命名和动画协议 → 基础躯干 → 头部/肩甲/道具模块 → 章节贴图配色。持盾姿态、冲撞头部、远程武器、隐身轮廓和背部棺架不能只靠换色。精英可用同模型更明显的肩部、纹样和有限描边，不另做一整套身体。

三类现有友军召唤物额外提供共用骨架参考：战士、护卫、射手。友军用短披片、胸部标记和武器形状区分，不能只依赖发光颜色；与敌方骷髅保持可辨差异。

## 后续特效与打击感

本轮只提供分镜，不生成可直接运行的序列帧或接入效果。优先次序为主角动作支撑与接触帧 → 敌人受击姿态 → 随武器方向的刀光 → 局部命中闪白/碎片 → 镜头和音效配合。

轻斩、重锤、法术需要不同的蓄力、接触和收势：轻斩轨迹窄且迅速消退；重锤突出身体下压、地面接触和较重碎片；火焰突出小而亮的核心与短余烬。华丽程度来自形状、节奏和方向，不堆满屏透明粒子。延续现有特效对象池，后续新增表现也要可回收。

## 本轮验收边界

检查名单完整、主角跨图识别一致、三视图能解释主要体块、Boss 阶段与现有玩法对应、手机可读性与模型复用建议。AI 参考图可能存在局部左右手、透视和小附件不一致；正式建模以基础三视图的统一骨架和实际挂点为准，不将图中文字当作数值配置。后续模型制作时再用游戏多角度截图验证，不在本轮启动 Blender、替换模型或做压力测试。
