# P3：地图与怪物纵向样板

状态：P3 代码交付完成，基本逻辑检查与生产构建通过。停在 P3，等待用户试玩验收，不进入 P4。交付分支为 `main`。

## 本阶段内容

- 石卫遗迹粗模主题。新局使用分支汇合、环路捷径、不对称区域三类结构，6–8 个房间，矩形、切角和 L 形房间组合。地图规模不随楼层增长；固定主线目标仍是 `room-4` 与 `room-1`。
- 四种战术空间：柱庭、破损防线、分隔回廊、侧翼环道。障碍提供遮挡、分路和绕侧机会，连接通道保留可走空间。商店继续独立出现在安全房的地图格子，每三层至少一次。
- 三类机制敌人：护卫正面减伤，但转向有速度限制，侧后及攻击暴露期可突破；支援者以连线预告治疗，可直接命中打断，最多治疗三次；控制者先锁定落点预警，再生成限时危险区，可在施法时打断。
- 三套遭遇配置：护卫仪式、追猎交叉火力、裂地围猎。按楼层逐步引入，数量受房间空间限制，普通遭遇最多八只；支援者和控制者各自限制数量，避免堆叠机制堵死房间。
- 第 25 层最终 Boss“遗迹监守者”：锁定方向扇形、双重落点、有限援军三阶段；完成技能后核心暴露 2.4 秒，提供集中输出窗口。预警范围与伤害范围一致，扫击可绕侧，场景障碍可阻挡伤害射线。
- 阶段 Boss 修正冲锋先行动后预警的问题，并给援军增加落点预警。最终 Boss 与阶段 Boss 援军都限制在本房间，数量设上限。

## 同轮燃烧修复

燃烧原本已有持续扣血，但缺少清楚的独立反馈。现在燃烧目标会有跟随身体的火焰粒子、橙色血条与明暗反馈，头顶汇总显示实际燃烧扣血。粒子按需创建并重复使用；燃烧结束、死亡或换层后收尾。火种天赋命中保证点燃；旧怪物的燃烧硬免疫调整为抗性，保留火系构筑的作用。

## 模块与存档

- `MapLayout` 负责路线图，`FloorGenerator` 负责格子空间，`RoomGeometry` 提供房间掩码与中心。遭遇识别、屏障、刷怪、标记和小地图共同使用真实房间范围。
- `data/encounters` 管理组合，`EncounterMechanics` 管理机制状态，`MechanicVisual` 管理提示粗模；最终 Boss 使用独立控制器。`Game` 保留编排职责。
- 存档记录地图生成版本。既有局的当前楼层沿用旧生成器与坐标，下一层切换新地图；新开局立即使用新生成器。
- 支援者剩余治疗次数与机制冷却保存。读档取消尚未完成的普通施法并保留恢复冷却，已生成的普通危险区不恢复，避免无预警伤害。最终 Boss 保存阶段、周期、暴露窗口和未完成预警，并恢复可见预警。
- 当前仍使用粗模和基础材质；正式统一美术、几十种技能、更多流派与第二主题按后续阶段推进。本阶段不声称已完成平衡调优或真实设备性能验证。

## 用户验收路径

1. 新开一局，观察路线与房间形状；进入战斗房确认全部出入口封锁，清完后可离开。
2. 火系点亮火种，以火球点燃敌人后暂停攻击，确认头顶燃烧数字、血量下降和持续火焰。
3. 第 3 层起观察护卫与治疗连线；绕到护卫侧后输出，直接击中正在施法的支援者。
4. 第 6 层起观察控制者落点，离开预警后确认有安全走位空间；施法中命中它检查打断。
5. 每五层观察 Boss 预警，第 25 层检查三阶段和橙色核心窗口。中途保存退出再继续，确认地图位置、治疗次数和最终 Boss 预警恢复合理。

检查遵循用户要求，仅做基本逻辑检查及 TypeScript / 生产构建，不运行全量测试、浏览器自动化或手机压力测试。

检查结果：三种结构各取一个样本，6–8 房、可走面积 647–823 格，经过两个主线目标的路线为 62–63 格；房内入口连通，第三层必有商店且不与宝箱重叠。旧版本单样本与 Git HEAD 原生成器输出完全一致。护卫正背面伤害、支援治疗余量恢复、最终 Boss 预警先于伤害、预警恢复、暴露倍率、阶段切换和清理通过基本检查。`npm run build` 通过；仍有主包超过 500 kB 的体积提示，未做真实设备性能验证。
