# 发布前性能复盘（2026-09-13）

本轮是代码热路径检查和基础行为验证，不是真机帧率测评。优先减少运算和内存分配，不降低画质，不调整战斗数值、掉落、AI 更新频率或存档规则。

## 已处理

- `ProjectileSystem`：同步碰撞步骤复用射线、碰撞盒及向量，避免每颗子弹每帧创建七个 Three.js 临时对象。临时对象不返回给调用方；伤害回调仍在碰撞步骤结束后执行。保留候选顺序、同距离判定、穿透和击退后的查询逻辑。
- `SpatialQueries`：墙体射线检测每个实体格不再分配四个边界数组，保留 X/Y/Z 检测顺序、半径扩张和浮点运算规则。此路径同时服务子弹和其他世界射线调用。
- `SummonCommandBar`：人数、模式、提示文字不变时不重写 DOM；无召唤配置时跳过布局查询。找不到触屏技能按钮时最多每 250 毫秒重试一次布局定位，避免电脑端逐帧强制测量；窗口尺寸变化后仍会重定位。

## 已有保护

- 粒子、部分技能视觉和伤害数字已有复用池；粒子和技能视觉分别有 160、48 个活动上限。
- 音效最多 18 个活动声源，存在事件间隔、距离筛选和优先级；解码缓存限制为 24 MiB，音频加载并发为 3。
- HUD 主状态和小地图按 0.1 秒间隔更新，属性已有缓存，子弹已有空间候选筛选。

## 验证

- 独立保留旧墙体射线实现，1,000 组随机射线验证地图边缘、平行轴、地面和半径扩张结果一致。
- 原有 800 组子弹对照以及击退/生成后的索引更新、穿透、暂停中断、伤害数字轨迹、属性缓存、存档候选、HUD 检查通过。本轮共运行 8 项相关测试。
- TypeScript 与生产构建通过；主 JavaScript 约 1.39 MB，gzip 约 411 KB，仍有构建体积提示。

## 打包后的真机验收重点

- 低端和中端 Android 设备各跑一次群怪、召唤、连续投射物与 Boss 战，观察持续帧时间、内存和发热；本轮未提供真机 FPS 提升百分比。
- 自动存档仍每 4 秒进行快照、验证和同步本地存储；若卡顿呈固定周期，应在打包环境记录该阶段耗时，再决定异步持久化方案，避免发布前贸然改变保存可靠性。
- 多模型、动态灯光和透明特效的 GPU 开销需要实际渲染分析才能排序，不能用代码检查推断为主要瓶颈。
- 切后台再返回、连续换层与升级覆盖安装后，确认画面恢复及局外天赋、已有存档仍可读取。网页端的构建通过不等于 Android 安装包已完成验收。
