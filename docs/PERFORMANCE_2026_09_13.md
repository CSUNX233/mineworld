# 战斗持续卡顿：运算逻辑首轮优化

本轮遵照用户补充要求，优先优化游戏运算；没有调整分辨率、灯光数量、阴影、贴图或特效画质。尝试中的动态分辨率功能已撤下，未保留在代码中。

## 排查结论与边界

桌面 Chromium 的 Android 横屏模拟、1000×460、DPR 1 中，5/10/18/25 层短时采样的游戏更新均值约 0.25–0.38 ms，渲染提交约 0.56–0.87 ms。没有复现用户手机的持续卡顿，不能把桌面数据当作手机帧率或断言唯一根因。

逻辑中确认存在可去除的重复工作：不同目标的寻路距离场反复检查相同屏障边；房间查询频繁构造坐标字符串；新敌人创建并继续更新不可见的旧模型；章节 AI 按敌人重复扫描全体敌人与装置。它们增加 CPU 工作量和临时对象压力，手机上尤其值得先处理。

## 已实施

1. `RoomGeometry` 将字符串集合改为连续数字掩码，保留不规则房间、空掩码、矩形以外的掩码单元和非整数查询的原有结果。
2. `Navigation` 保留 16 个目标距离场的 LRU 与原有邻居顺序；新增通行边缓存并复用定长队列。屏障数组变化、补给架/破坏面板触发地图失效时，一并清理。没有减少寻路频率或改变走位规则。
3. `MonsterSpawner.createActor` 在模型已加载时直接构建新外观，避免先创建隐藏的旧身体。新敌人不再每帧更新旧模型部件，并直接保留外观引用。头顶标记按实际显示模型计算高度；属性和碰撞判定仍使用原有逻辑。
4. `LateChapterController` 缓存房间查询；军旗支援按房间汇总，避免嵌套全体扫描；施法检查直接遍历，不复制整张 Map；设施只在视觉状态变化时更新材质；死亡后释放 AI 引用。

## 基础验证与结果

- 4,096 次新旧寻路方向查询一致，覆盖 5/10/18/25 层、开门、锁门、解锁与地图单元改变。
- 11,722 次房间查询一致，包含边缘及小数坐标。
- 同组寻路比较：旧实现 87.7 ms，新实现 24.3 ms，减少约 72%。这是专项样本，不是整局帧率提升幅度，也不是手机跑分。
- 十二种新敌人的对象合计从 168 降至 96；基础属性、速度、初始状态和坐标一致，实际模型存在。
- 关卡加载、六类设施恢复、十二类敌人更新、楼梯、连续冲撞、跳跃避波、试炼第二波不重复与资源清理通过基础检查。
- `npm run build` 与 `git diff --check` 通过。浏览器记录只有缺失 favicon 的 404，没有游戏运行异常。

原始记录位于 [本轮采样目录](performance/2026-09-13/)。下一次应在用户实际卡顿的手机上验证战斗体感；当前不承诺已经消除全部卡顿，也未开展百局平衡或长期压力测试。

## 高频特效对象池与敌人脱困

- Effects 的碎片、冲刺拖尾、刀光、命中与烟雾等复用 Mesh/Sprite、材质和状态向量；回收时脱离场景，借出时重置颜色、旋转、透明度、速度和寿命。保留原有粒子 160、视觉特效 48 的上限以及视觉表现。跨层保留池，完整销毁时释放材质和共享几何体，不销毁借用的贴图。这不代表所有投射物或敌人都已池化。
- 敌人在封锁战斗房内持续尝试移动约 3 秒、实际位移不足 0.25 米时，尝试移到本房间附近的合法地面。落点避开屏障、入口、交互物、其他敌人，并与玩家保持至少 3 米距离；没有安全落点就等待。传送后有 8 秒冷却，不改变血量、归属房间或奖励。
- 站立、蓄力、冻结、持续移动及玩家不在该房间时不触发恢复。普通、章节和 Boss 的移动路径已接入移动意图。
- 基础验证：预热 54 个特效对象后重复 20 轮未创建新渲染对象；复用状态、数量上限及销毁检查通过。脱困时间、安全地面、高度、冷却和不误触发检查通过，实际 AI 被墙困住的追逐场景也成功恢复。构建与差异格式检查通过。记录见 `performance/2026-09-13/effects-pool-recovery.json`；此结果不代表手机帧率实测。
